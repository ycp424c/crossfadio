# 运维文档的公开边界

本仓库不保存任何可定位、访问或操作真实生产环境的信息。完整生产运维手册只保存在本机：

```text
.local/ops/production-runbook.md
```

该文件被 Git 忽略，是线上日志、部署、服务状态、配置核验、白名单与故障排查的本地真相源。执行任何线上操作前必须先读取它；文件不存在或信息过期时，应停止操作并由环境所有者恢复或更新，不能根据提交历史、聊天记录或代码默认值猜测生产参数。

## 不得提交的内容

- 云账号、区域、实例 ID、实例名、对象存储 bucket 和 CLI profile。
- 公网/内网地址、端口映射、真实域名及可定位服务的 URL。
- 服务器用户名、绝对目录、日志/数据库/白名单路径和部署拓扑。
- 真实用户 ID、管理员 ID、白名单内容或用户画像。
- 当前 provider/model、生产环境变量值、凭据、token、cookie、签名 URL。
- 能直接对真实环境执行的完整命令、历史事故现场和备份目录名称。

## 仓库内可以保留的内容

- 与代码行为直接相关、且不依赖真实环境的配置项语义。
- 使用占位符的部署脚本和本地配置模板。
- 不包含生产定位信息的验证原则、回滚原则和隐私边界。
- 单元测试、脱敏 fixture 约束与只读查询的安全要求。

## 本地文件

- `.local/ops/production-runbook.md`：完整生产运维手册，仅本机保存。
- `.local/ops/production.env`：`scripts/deploy.sh` 使用的真实部署参数，仅本机保存。
- `scripts/ops.env.example`：可提交的占位模板，不含真实值。

部署脚本默认读取 `.local/ops/production.env`，也可通过 `CROSSFADIO_OPS_ENV_FILE` 指向其他本地私密配置。不要把本地文件内容粘贴到 issue、MR、任务对话或第三方服务。

## 提交前检查

至少执行：

```bash
git status --short
git diff --cached
git grep -n -I -E 'InstanceId|CROSSFADIO_ADMIN_NCM_ID=|https?://([0-9]{1,3}\.){3}[0-9]{1,3}'
```

命中不一定都是泄露，但必须逐条确认。若真实信息曾进入 Git，仅删除当前文件不够，还需要重写所有受影响分支和标签的历史，并通知协作者重新同步。
